## بخش ۱ — کامپیوتر چطور کار می‌کند و کدنویسی چیست

**هدف:** دانشجو بتواند بگوید برنامه چیست و چرا خطا بخشی از کار است.

> «تا امروز هر بار که با کامپیوتر کار کرده‌اید، از نرم‌افزاری استفاده کرده‌اید که یک نفر دیگر نوشته است. امروز شما آن یک نفر می‌شوید. برنامه‌نویسی چیزی شبیه همان کاری است که سال‌ها در آزمایشگاه می‌کنید: نوشتن یک دستور کار، دقیق و بدون ابهام.»

سه جملهٔ کلیدی:

1. کامپیوتر «باهوش» نیست؛ فقط دقیق و سریع است.
2. برنامه = دستورهایی که به ترتیب اجرا می‌شوند.
3. خطا نشانهٔ خرابی شما نیست؛ اطلاعات است. **حدس بزن، اجرا کن، بخوان، اصلاح کن.**

## بخش ۳ — `print`، `input`، متغیر، نوع مقدار

```python
print("Hello, Python!")
print("PM2.5 guideline:", 15, "ug/m3")
print("2 + 3 =", 2 + 3)   # 2 + 3 = 5
print("2 + 3")            # 2 + 3  ← این یکی متن است، نه محاسبه
```

> «چیزی که داخل `" "` است، متن است؛ هر چیزی بیرونش، کد. `print` چند چیز را با هم چاپ می‌کند و بینشان فاصله می‌گذارد.»

### متغیر و نوع

```python
city = "Tehran"
pm25 = 48.3
n_stations = 12
is_valid = True

print(city, pm25, n_stations, is_valid)
print(type(city), type(pm25), type(n_stations), type(is_valid))
```

> «متغیر یک برچسب است روی یک مقدار. `pm25 = 48.3` یعنی «هر جا `pm25` دیدی، ۴۸.۳ را بگذار». اسم خوب، نیمی از خوانایی کد است.»

چهار نوع امروز: `str`، `int`، `float`، `bool`. `type()` ابزار بازرسی است.

**هشدار عملی:** اعداد را با صفحه‌کلید فارسی تایپ نکنید. `۴۸.۳` برای پایتون عدد نیست؛ `SyntaxError` می‌گیرید.

### حساب و تبدیل

```python
a, b = 10, 4
print(a + b, a - b, a * b)
print(a / b)    # 2.5   تقسیم همیشه اعشاری است
print(a // b)   # 2     تقسیم صحیح
print(a % b)    # 2     باقی‌مانده
print(a ** b)   # 10000 توان

print(int("42") + 1)      # 43
print(str(75) + " ug/m3") # 75 ug/m3
print(int(3.99))          # 3   برش، نه گرد کردن
```

### ورودی و f-string

```python
city = input("City: ")
pm25_text = input("PM2.5 (ug/m3): ")
print(type(pm25_text))    # str ! حتی اگر کاربر عدد بزند

pm25 = float(pm25_text)
print(f"{city}: PM2.5 = {pm25:.1f} ug/m3")
```

> «`input()` همیشه متن برمی‌گرداند. تا تبدیل نکنید، نمی‌توانید جمع بزنید. این شایع‌ترین خطای هفتهٔ اول است.»

خطای کلاسیک: `int("48.3")` → `ValueError`.

### لحظه‌های پیش‌بینی

| عبارت | جواب | چرا مهم است |
|---|---|---|
| `0.1 + 0.2` | `0.30000000000000004` | کامپیوتر اعشار را دقیق نگه نمی‌دارد |
| `10 / 4` | `2.5` | `/` همیشه اعشاری است |
| `"3" + "4"` | `"34"` | متن + متن = چسباندن |
| `int("48.3")` | `ValueError` | `int` اعشار نمی‌پذیرد |

**چک‌پوینت:** برنامه‌ای بنویسید که اسم شهر و PM2.5 را بگیرد و یک جملهٔ کامل چاپ کند.

if pm25 < 15:

## بخش ۹ — خواندن خطاها

```
Traceback (most recent call last):
  File "broken.py", line 3, in <module>
    print(cities[5])
IndexError: list index out of range
```

> «از پایین شروع کنید. خط آخر دو چیز دارد: نوع خطا و توضیح. بالاتر، محل خطا: فایل، شمارهٔ خط و علامت `^`. مهم‌ترین اطلاعات آخر است.»

| کاری که می‌کنید | خطا | جمله‌ای که باید بگویید |
|---|---|---|
| `if pm25 = 50:` | `SyntaxError` | جمله‌بندی غلط؛ `=` را با `==` عوض کن |
| بدنهٔ `for` بی‌تو رفتگی | `IndentationError` | پایتون از تو رفتگی می‌فهمد چه چیزی داخل حلقه است |
| `print(pm_25)` | `NameError` | اسم ناشناس: نه غلط نوشتی، نه تعریفش کردی |
| `int(input())` با ورودی `48.3` | `ValueError` | مقدار قابل تبدیل نیست؛ `int` اعشار نمی‌پذیرد |
| `cities[5]` | `IndexError` | بیرون از محدوده |
| `station["so2"]` | `KeyError` | کلید نیست |

## بخش ۱۰ — آزمایشگاه هرم

مسئله: برای `n` خط، شکلی مثل این چاپ شود:

```
    *
   ***
  *****
 *******
*********
```

هر خط سه چیز با هم عوض می‌شود:

| خط (i) | فاصله | ستاره |
|---|---|---|
| ۱ | ۴ | ۱ |
| ۲ | ۳ | ۳ |
| ۳ | ۲ | ۵ |
| ۴ | ۱ | ۷ |
| ۵ | ۰ | ۹ |

پس:

```python
def pyramid(n, star="*"):
    for i in range(1, n + 1):
        spaces = n - i
        stars = 2 * i - 1
        print(" " * spaces + star * stars)

pyramid(5)
pyramid(5, "#")
```

سه چیز تازه و هر سه ساده:

- `" " * 4` یعنی «چهار فاصله پشت سر هم»؛ پایتون متن را در عدد ضرب می‌کند.
- `star * stars` هم همان کار را با ستاره می‌کند.
- `range(1, n + 1)` از ۱ تا خودِ `n` می‌شمارد؛ عدد آخر حساب نمی‌شود، برای همین `n + 1` نوشتیم.

> «هر دو تکه در یک `print` و با `+` به هم چسبیده‌اند؛ اگر با کاما جدا بنویسید، پایتون یک فاصلهٔ اضافه بینشان می‌گذارد و هرم کج می‌شود.»

**چرا `2 * i - 1` و نه `i * 2`؟** چون خط اول باید ۱ ستاره داشته باشد، نه ۲.

**سه خطای رایج:**

1. `i * 2` به‌جای `2 * i - 1` → خط اول دو ستاره می‌شود و هرم کج درمی‌آید.
2. فراموش کردن فاصله‌ها → هرم به دیوار سمت چپ می‌چسبد.
3. چاپ فاصله و ستاره در دو `print` جدا → هرم دو برابر ارتفاع پیدا می‌کند.

**معیار «تمام شد»:**

- `pyramid(5)` پنج خط هرم درست چاپ می‌کند.
- `pyramid(5, "#")` همان هرم را با `#` می‌سازد.
- `pyramid(0)` هیچ چیز چاپ نمی‌کند و خطا هم نمی‌دهد.
- می‌توانید توضیح بدهید چرا تعداد ستاره‌ها `2 * i - 1` است.

اگر بیشتر خواستید: هرم وارونه، لوزی و جدول ضرب n × n با دو حلقهٔ تو در تو — هر سه با همین ابزارها ساخته می‌شوند. برگهٔ کامل: `pyramids-lab.md`.

## بخش ۱۲ — جمع‌بندی و تکلیف

از «کامپیوتر چطور کار می‌کند» تا هرمی که خودمان ساختیم. مهم‌ترین چیزی که تمرین کردیم، خودِ پایتون نبود؛ عادت **«حدس بزن، اجرا کن، بخوان، اصلاح کن»** بود.

**تکلیف:**

1. همهٔ فایل‌های کلاس را یک بار اجرا کنید و هر خطا را بلند بخوانید.
2. سطح ۴ و ۵ برگهٔ آزمایشگاه هرم را کامل کنید.
3. تابعی بنویسید که لیستی از اعداد بگیرد و **میانگین را `return` کند** (نه `print`).

اگر `if` و `for` برایتان هنوز لق است، نوشتهٔ بعدی همین‌جا برای شماست: **«`if` و `for` در پایتون، برای کسی که تازه شروع کرده»** — بدون عجله و با مثال‌های کوتاه.
